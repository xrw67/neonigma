## 1. 产品概述

### 1.1 背景与定位

复刻经典掌上电子解谜玩具「超级密码机」的玩法:在一块 4×7 的彩色棋盘上,玩家通过多轮猜测和逐轮反馈的提示灯,在 7 步内推理出隐藏的 4 位颜色密码。本质是经典桌面游戏 Mastermind(珠玑妙算)的电子化版本,原型设备在此基础上做了三点强化:

1. **起始线索**:单人模式第一行由系统预先给出一个猜测及其提示,玩家从第二行开始推理,降低上手门槛(适合 5 岁以上儿童);
2. **两种提示形态**:直接提示(每格逐一标注)与间接提示(行侧聚合计数),后者信息更模糊、更烧脑;
3. **600 关卡制 + 双人对战**:100 关简单 + 500 关进阶的闯关体系,以及"出题者 vs 破译者"的本地对战。

iOS 版在完整复刻以上玩法的基础上,利用触屏、触觉反馈、进度云同步等平台能力做体验增强。

### 1.2 产品目标

- **G1 完整复刻核心玩法**:提示规则、7 步限制、起始线索、两种提示形态、600 关结构、双人对战,与原型行为一致;
- **G2 触屏体验优于实体机**:选色、填格、提交的操作效率高于原型机的"旋钮+按键",保留"打字机式"的按键音与触觉爽感;
- **G3 儿童友好**:5 岁以上可独立上手,大点击区域、交互式教程、色盲辅助;
- **G4 离线优先**:核心玩法零网络依赖,完整本地进度保存;
- **G5 可验证的正确性**:提示算法 100% 单元测试覆盖,全量关卡经过求解器验证可解。

### 1.3 合规与命名声明(重要)

- **玩法机制不受版权保护**:Mastermind 类推理玩法可自由实现;但「计客」「GiiKER」「超级密码机 Super Decoder」是其注册商标,**游戏名称、图标、美术、宣传物料不得使用或模仿**。

## 2. 原型拆解(参考基准)

以下事实来自 GiiKER 官方产品页与官方英文说明书(V3.0,2025.02),作为本项目的复刻基准。

### 2.1 硬件构成 → iOS 对应物

| 原型硬件 | 功能 | iOS 对应设计 |
|---|---|---|
| 4×7 彩色 LED 矩阵(Color Indicator) | 每行一次猜测,共 7 行 | 对局页主棋盘 |
| 直接提示灯(Direct Hint Indicator,行下方) | 逐格 3 态提示 | 每格下方状态点(§3.2) |
| 间接提示灯(Indirect Hint Indicator,行侧) | 行侧聚合计数 | 行右侧计数徽章(§3.3) |
| 旋钮(Twist Button:SELECT/CONFIRM) | 旋转选色、短按换位、长按确认 | 点选格子 + 调色盘(§4.4) |
| 拨动开关(Tele Button:ON/OFF、SOLO、DUO) | 模式切换 | 主菜单模式入口 |
| 提示按钮(Hint Button) | 切换直接/间接提示 | 开局选择 + 设置项 |
| 数字屏(Number Screen) | 显示关卡号 | 对局页关卡号/双人倒计时 |

### 2.2 原型规则事实

- 密码为 **4 位颜色**,7 步内破译;7 种颜色、不重复,共 **840 种**可能密码(7×6×5×4);
- 提示灯三态:**颜色且位置正确 / 颜色对但位置错 / 颜色不存在**;
- 单人模式:第 1 行为系统给出的起始线索,玩家**还有 6 次猜测机会**(棋盘共 7 行);
- 双人模式:出题者设置密码并**设置限时**,破译者有 **7 次猜测机会**;
- 关卡:**简单 100 关(直接提示)+ 进阶 500 关(间接提示)= 600 关**,可跳关;
- 失败后**不显示答案**,短按重试;游玩中可随时短按预览并切换关卡;
- 5 分钟无操作自动关机;长按旋钮静音。

## 3. 游戏规则规格(iOS 版)

### 3.1 基本定义

| 项 | 规格 |
|---|---|
| 颜色集 | 7 色:红 R、橙 O、黄 Y、绿 G、蓝 B、紫 P、白 W(色值见 §6.2) |
| 密码长度 | 4 位 |
| 组码规则 | 7 色中取 4 色,**不重复**,有序排列,共 840 种 |
| 棋盘 | 7 行 × 4 列;第 1–6 行为玩家可提交的猜测行,第 7 行为最后一次机会(单人模式第 1 行被起始线索占用,见 §4.2) |
| 提示形态 | 直接提示(简单模式)/ 间接提示(进阶模式),每局开始前确定,局内不可切换 |

### 3.2 直接提示(简单模式,E1–E100)

对玩家所猜行的**每一格**,在该格正下方给出一个独立状态点,三态:

| 状态 | 含义 |
|---|---|
| 🟢 绿 | 该格颜色与密码该位置完全一致(对色对位) |
| ⚪ 白 | 该颜色存在于密码中,但不在该位置(对色错位) |
| ⚫ 灭 | 该颜色不在密码中 |

**特点**:提示与格子一一对应,玩家可快速锁定每个颜色"存不存在、在不在这位",门槛低,适合儿童与新手。

### 3.3 间接提示(进阶模式,A1–A500)

对玩家所猜行的**整行**,在该行右侧给出聚合计数徽章:

| 计数 | 含义 |
|---|---|
| 绿点数 | 全行中"对色且对位"的格子总数 |
| 白点数 | 全行中"对色但错位"的格子总数 |

**特点**:只给数量、不给对应关系,玩家需自行设计排除实验,推理深度显著高于直接提示。

### 3.4 提示算法统一规则与示例

两种提示共用同一套底层判定 `evaluate(code, guess) → (greens, whites)`,直接提示是它的逐格展开,间接提示是它的聚合计数,**两者必须严格等价**(验收项 §11)。

**分配规则(处理猜色重复)**:

1. 第一遍:对每个位置 i,若 `guess[i] == code[i]`,记 1 个绿,并将该位置与该密码色标记为已消费;
2. 第二遍:对剩余位置按**从左到右**顺序,若 `guess[i]` 存在于密码中未被消费的颜色里,记 1 个白,并消费该密码色;
3. 其余格子为灭。

**示例**(密码 = `[红, 绿, 蓝, 黄]`):

| 玩家猜测 | 直接提示(逐格) | 间接提示 | 说明 |
|---|---|---|---|
| 绿·红·蓝·白 | ⚪ ⚪ 🟢 ⚫ | 1 绿 2 白 | 蓝对位;绿、红存在但错位;白不在密码 |
| 蓝·蓝·白·白 | ⚪ ⚫ ⚫ ⚫ | 0 绿 1 白 | 蓝:第 1 格消费唯一名额,第 2 格不再计 |
| 黄·蓝·绿·红 | ⚪ ⚪ ⚪ ⚪ | 0 绿 4 白 | 四色全对、全错位 |
| 红·绿·蓝·黄 | 🟢 🟢 🟢 🟢 | 4 绿 | 破译成功 |

### 3.5 胜负判定

| 事件 | 判定 |
|---|---|
| 胜利 | 某行提交后 `evaluate` 返回 4 绿,立即结算(§4.10) |
| 失败 | 第 7 行(单人)或第 7 次提交(双人)的提示展示完毕仍未 4 绿 |
| 双人超时 | 破译者倒计时归零仍未破译,出题者胜 |

**失败后是否显示答案**:原型明确不显示、鼓励重试。**本作默认失败后提供「查看答案」**,并在设置中提供开关(默认开)复刻原版体验。——此项为对原型的刻意体验改进,**已定稿:默认开(2026-10-01 评审,Q3)**。

### 3.6 随机与确定性

- **禁止使用系统随机数**生成关卡。使用固定算法的带种子 PRNG(建议 SplitMix64),`seed = 关卡全局编号`,离线生成 600 关的 `(密码, 起始线索)` 查找表,随包内置;
- 由此保证:任何设备上同一关卡密码一致,是**每日挑战**(§4.8)与未来异步对战的前置条件;
- 起始线索同样由种子生成,并按关卡难度带约束筛选(见 §4.5 难度曲线)。

### 4.2 单人闯关模式

- **FR-S1** 进入关卡后,第 1 行自动预填系统起始线索,并立即显示该行提示(直接或间接,按关卡所属模式);玩家从第 2 行开始,最多提交 **6 次**。
- **FR-S2** 提交后新提示以动画展示(约 300ms 逐格/逐点点亮),期间禁止操作。
- **FR-S3** 对局中可「重开本关」(重置为只有起始线索的初始态,不消耗任何东西);可随时退出进入关卡选择页,进度(已提交的行)保留至本次会话结束。
- **FR-S4** 破译成功按猜测次数(不含起始线索行)给星:**≤2 次 3 星,≤4 次 2 星,其余 1 星**;星级取历史最好成绩,可重复挑战刷星。
- **FR-S5** 失败后可:重试本关 / 查看答案(若设置开启,答案以一次性行展示且不记成绩)/ 跳转选关。
- **FR-S6** 跳关:任意已有关卡均可直接进入(复刻原型"可跳过简单关直接进阶"的设计);未完成的关卡不阻挡后续关卡。

### 4.3 双人对战模式(本地 pass-and-play)

- **FR-D1 流程**:主菜单选「双人对战」→ 选择提示形态(直接/间接,同 §3.1)→ 进入出题页 → 出题者设密码、设限时 → 「交给破译者」过渡遮罩页 → 破译者开始(7 次机会)→ 结算。
- **FR-D2 出题页防偷看**:全屏遮罩态,仅显示"出题者操作中"与 4 个待填格;点击格子循环/调色盘选色;确认时校验 **4 色互不相同**,不满足则抖动提示且不可提交。
- **FR-D3 限时**:可选 不限时 / 1 / 3 / 5 / 10 分钟(默认 3 分钟)。破译者对局页顶部倒计时,最后 30 秒变红 + 心跳触觉;归零判负(出题者胜)。
  - 注:原型为"旋钮选时间",档位未知,此处档位为本作定义(开放问题 §12)。
- **FR-D4 破译者视角**:与单人棋盘一致,但无起始线索,7 行全部由玩家提交。
- **FR-D5 结算**:显示答案、用时/剩余时间、双方比分;提供「换边再来」(出题者与破译者互换,比分累计)与「返回主菜单」。
- **FR-D6** 双人模式不计入单人统计与成就(防刷)。

### 4.4 对局界面与交互

界面布局(竖屏):

```
┌────────────────────────────┐
│ ← 返回   第 A-137 关   ⚙    │
│        [倒计时/步数]        │
│ ┌───┬───┬───┬───┐          │
│ │ 🟪 │ 🟩 │ 🟦 │ ⬜ │ ← 第7行      │
│ ├───┼───┼───┼───┤          │
│ │ …  │    已提交行(含提示) │
│ ├───┼───┼───┼───┤          │
│ │ 🟥 │ 🟧 │    │    │ ← 当前编辑行 │
│ └───┴───┴───┴───┘ ⚪⚪ ← 行侧/格下提示│
│                            │
│   调色盘: 🟥🟧🟨🟩🟦🟪⬜      │
│   [清空]      [ 确 认 ]     │
└────────────────────────────┘
```

- **FR-P1 选色**:点按空格/已填格选中(高亮呼吸动画)→ 点调色盘颜色填入;支持在格子上**上下滑动**直接循环切换颜色(对应原型"旋钮选色"手感);再次点击其他格切换选中。
- **FR-P2 行内编辑**:未提交的行可任意改色;长按格子清空该格;「清空」重置整行。
- **FR-P3 提交**:4 格填满后「确认」可用;对应原型"长按确认"——本作改为**点按确认**(降低儿童操作成本),长按交互弃用。提交后该行锁定,播放逐格落子音 + 逐点点亮提示动画。
- **FR-P4 撤销限制**:已提交行不可修改、不可撤回(与原型一致,保证推理记录的严肃性)。
- **FR-P5 触觉反馈**:选中格 light impact;填色 light;提交行 medium;提示点亮逐点 light;破译成功 success notification;失败/超时 error notification。均可关。
- **FR-P6 音效**:复刻"打字机式"机械按键音(选色咔哒、提交铿锵)、破译成功音效、失败低沉音;首次破译、连破等有专属音效。**音效为体验核心之一,需专门设计与原型听感对齐**(MIDI 合成或采样,见 §6.3)。
- **FR-P7 关卡号屏**:对局页显示当前关卡编号(如 `A-137`),双人模式该区域显示倒计时——对应原型数字屏。
- **FR-P8** 防误触:提示动画播放期间输入冻结;退出弹确认(对局进行中)。

### 4.5 关卡选择与进度

- **FR-L1** 关卡页按章节组织:**简单 E1–E100(直接提示)**;进阶 A1–A500 分 10 章(A001–050 … A451–500,间接提示),章节命名待定(视觉主题化,如"学徒→侦探→大师")。
- **FR-L2** 每关展示:编号、星级(0–3)、当前进行标记;点按直接开始(自由跳关,FR-S6)。
- **FR-L3 难度曲线(起始线索信息量递减)**:

| 关卡段 | 起始线索约束 | 体验目标 |
|---|---|---|
| E001–E020 | 线索提示含 ≥2 绿 | 教学区:几乎送分,建立信心 |
| E021–E100 | 线索提示含 1–2 绿 | 巩固直接提示读法 |
| A001–A150 | 线索提示含 1 绿 | 学会间接提示推理 |
| A151–A350 | 线索 0 绿、白 ≥2 | 中等:需设计排除实验 |
| A351–A500 | 线索 0 绿、白 ≤1 | 高难:低信息开局,考验系统推理 |

- **FR-L4 进度保存**:本地持久化(关卡星级、完成状态、设置、统计);杀进程后状态无损。iCloud 同步为 P1。
- **FR-L5** 600 关查找表构建后,须用离线求解器脚本验证**每一关在 6 次玩家猜测内可解**,不可解关卡重新生成(验收项 §11)。

### 4.6 新手引导

- **FR-T1** 首次启动进入交互式教程(可跳过,可从设置重进):3 步——①点格子、选颜色;②提交、看懂 3 态直接提示;③利用起始线索 1 步破译,给予成功庆祝。
- **FR-T2** 首次进入进阶模式 A001 前,弹 1 页图解:"间接提示只告诉你有几个对,不说在哪"。
- **FR-T3** 教程关卡固定用 E001 的谜面,完成后无缝进入 E002。

### 4.7 统计与成就(P1)

- 统计页:总局数、胜率、平均破译步数、最快破译(双人)、3 星关卡数、连续通关纪录(streak);
- Game Center 成就示例:「初露锋芒」破译 E010、「逻辑大师」3 星达成 50 关、「两人对决」双人首胜、「日积月累」每日挑战 7 连;
- 排行榜:进阶模式通关数、每日挑战连胜。

### 4.8 每日挑战(P1)

- **FR-C1** 每天全服同一道题:由 `seed = 当天日期(UTC+8)` 从规则引擎生成(直接/间接提示隔天交替);
- **FR-C2** 记录当日步数与用时,本地保存打卡日历与最长连续天数;
- **FR-C3** 无网络也可游玩,联网时上报 Game Center 排行(可选)。

## 6. 视觉与音频

### 6.1 视觉风格(原创)

- **不复刻原型机身造型与 UI 布局**;以"复古电子解谜机"为意象做原创演绎:深色哑光底板 + 发光圆角"色块灯珠"、轻微灯箱辉光、翻牌/落子动效;
- 整体调性:儿童可亲、成年不觉幼稚;避免与原型近似的整体外观(trade dress 风险,见 §1.3);
- 关卡章节以色彩主题区分(如简单=暖色时段,进阶=霓虹夜色)。

### 6.2 色彩与色盲符号

| 颜色 | 参考色值 | 色盲辅助符号 |
|---|---|---|
| 红 R | `#E5484D` | ■ |
| 橙 O | `#F76B15` | ▲ |
| 黄 Y | `#FFC53D` | ● |
| 绿 G | `#46A758` | ◆ |
| 蓝 B | `#0091FF` | ★ |
| 紫 P | `#8E4EC6` | ✚ |
| 白 W | `#F2F0EF` | ✿ |

提示状态色:绿=成功绿、白=纯白、灭=底板灰。色盲符号同时服务于提示点(绿/白点旁可加 √/↻ 小标,评审定夺)。

### 6.3 音效与触觉

- 选色"咔哒"、换位"嗒"、提交"锵"——参考打字机/机械键盘听感,做一套 3–5 个变体避免重复感;
- 提示点亮:单音上行(绿)/中音(白)/静默(灭);
- 破译成功:8–12 音符上行小旋律;失败:2 音下行;
- 全部音效走统一总线,音量设置一键静音(对应原型静音功能);
- 触觉与音效同源触发,保证"手感"一致(§4.4 FR-P5)。

## 7. 技术方案建议

> **技术选型已定稿(2026-10-01)**:详见 `docs/技术选型.md`。本节保留为最初建议,与技术选型冲突处(如 iCloud 同步 API、SpriteKit、脚本工程化方式)以该文档为准。

### 7.1 架构

```
Neonigma/
├── Core/               # 纯 Swift 规则引擎,零 UI 依赖,可单测
│   ├── CodeBreakerEngine   # evaluate / 胜负 / 行状态机
│   ├── SeededRNG           # SplitMix64
│   └── LevelTable          # 600 关 (code, startClue) 查找表
├── Features/           # SwiftUI 页面(对局/选关/双人/教程/设置/统计)
├── Persistence/        # SwiftData:进度、设置、统计
├── Services/           # 音频、触觉、GameCenter、iCloud
└── Resources/          # 关卡表 JSON、音效、本地化
```

- UI:SwiftUI(棋盘用 `Grid` + 显式动画);如需复杂粒子(彩带)再局部引入 SpriteKit,默认不引入游戏引擎;
- 持久化:SwiftData;iCloud 同步用 SwiftData 内建 CloudKit 集成(`ModelConfiguration(cloudKitDatabase:)`,P1;原文误写 Core Data 的 `NSPersistentCloudKitContainer`,已修正——见 `docs/技术选型.md` §2.5);
- 音频:AVFoundation;触觉:CoreHaptics(自定义波形做"机械感")。

### 7.2 关键数据模型

```swift
struct Level { let id: Int; let band: Band; let code: [Color]; let startClue: [Color] } // Band: .easy / .advanced(章节)
struct GameSession { let levelID: Int?; let mode: Mode; var rows: [Row]; let hintKind: HintKind }
struct Row { var guess: [Color]; var hint: Hint } // Hint: .direct([CellHint]) | .indirect(greens: Int, whites: Int)
struct PlayerProgress { var stars: [Int: Int]; var settings: Settings; var stats: Stats }
```

### 7.3 工程验证脚本(随仓库)

- `scripts/gen_levels.swift`:离线生成 600 关查找表(JSON 随包内置);
- `scripts/validate.swift`:①直接/间接提示等价性(全枚举);②每关可解性(迭代深度优先求解器,验证 ≤6 次玩家猜测);③840 密码全量 evaluate 边界用例;
- 二者输出作为 CI 门槛。
