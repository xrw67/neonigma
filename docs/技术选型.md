## 2. 决策详情

### 2.1 平台与最低版本:iOS 17

**选择**:最低 iOS 17;iPhone / iPad universal(竖屏优先);visionOS / macOS 上架后评估(PRD Q7,SwiftUI 移植成本低)。

**理由**:
- 2026-10 覆盖率:iOS 17+ ≈ 99%、iOS 18+ ≈ 98.7%、iOS 26+ ≈ 90%(TelemetryDeck 2026-08,样本偏欧美,真实略低;Apple 官方口径更低)。目标用户含 5–12 岁儿童及其家长的旧设备,**覆盖优先于新 API**;
- 本作必需的能力线正好卡在 iOS 17:`@Observable`(Observation)、SwiftData、`.sensoryFeedback`、SwiftUI `Grid`;
- iOS 18 / 26 的 SwiftUI 增量(更强动画控制、Liquid Glass)对本作非刚需。

**备选与放弃原因**:iOS 18 —— 收益仅"少测一个大版本",覆盖损失虽小但无必要;iOS 26 —— 放弃约一成设备,对儿童向产品不可接受。

### 2.2 语言与工具链:Swift 6.4 / Swift 6 语言模式

**选择**:Xcode 27(Swift 6.4);新工程保持默认的 **Swift 6 语言模式**(Xcode 26 起配合 Approachable Concurrency 成为新项目默认:隐式 MainActor 隔离 + 渐进式并发检查)。

**理由**:规则引擎是纯函数,天然 Sendable;UI 层由隐式 MainActor 兜底。第一天就用 Swift 6 模式,避免日后补并发改造。

**注意**:`Core` 包保持平台无关(不 import UIKit/SwiftUI),这样它能同时在 macOS 命令行与 Linux CI 上构建。

### 2.3 UI 框架与架构:纯 SwiftUI + @Observable,不引入 TCA

**选择**:SwiftUI;每个 Feature 一个 `@Observable` 视图模型,由视图 `@State` 持有;跨页共享状态(进度、设置)用 `@Environment` 注入的服务对象。对局页棋盘用 `Grid` + 显式动画(与 VDD §10 一致)。

**理由**:2026 年社区共识——TCA 的收益(结构化副作用、可组合性)在大团队/复杂状态应用才兑现;本作状态机集中在一局游戏内,纯 `@Observable` 足够且无学习成本。

**备选与放弃原因**:TCA —— 稳定版 1.26.2 可用,但 Point-Free 已于 2026-04 宣布 2.0 重构(目前仅 beta、无发布时间表),现在引入等于预支一次大版本迁移;MV(无 VM)—— 视图与状态耦合,教程/双人等流程页反而难拆。

### 2.4 模块分层与工程组织

**选择**:仓库根放本地 SPM 包 `Core/`(Xcode「本地包」官方模式),App 为 Xcode 27 **文件夹式(synchronized)工程**:

```
Neonigma/
├── Core/                        # 本地 SPM 包(纯 Swift,零 UI 依赖)
│   ├── Package.swift            # 三个目标:library Core + executable GenLevels / Validate
│   ├── Sources/Core/            # CodeBreakerEngine(evaluate/胜负/行状态机)
│   │                            # SeededRNG(SplitMix64)· LevelTable(600 关查找表)
│   ├── Sources/GenLevels/       # swift run gen-levels → App Resources/levels.json
│   ├── Sources/Validate/        # swift run validate(等价性 + 可解性,CI 门槛)
│   └── Tests/CoreTests/         # Swift Testing(见 §2.9)
├── Neonigma.xcodeproj           # 文件夹式工程,引用 Core 为本地包依赖
│   └── Neonigma/
│       ├── Features/            # 对局 / 选关 / 双人 / 教程 / 设置 / 统计(每页 = View + ViewModel)
│       ├── Persistence/         # SwiftData 模型与容器
│       ├── Services/            # 音频 / 触觉 / GameCenter / iCloud(P1,薄封装)
│       └── Resources/           # levels.json、音效、Assets、Localizable.xcstrings
├── docs/  design/  …
```

**理由**:引擎与关卡工具脱离 Xcode 可独立运行(`swift run` / `swift test`),这是"关卡确定性 + 求解器验证"工作流的载体;文件夹式工程免掉文件引用维护,XcodeGen/Tuist 的核心卖点(生成、缓存、模块图)在单人小项目不兑现。

**备选与放弃原因**:全部代码塞进 App target —— 引擎无法在 Linux CI 测试、脚本无法复用;XcodeGen —— 社区维护放缓,对 Xcode 16+ 新工程格式支持仍滞后;Tuist —— 为规模化设计,本作体量用不上。

### 2.5 持久化:SwiftData(附降级预案)

**选择**:SwiftData 存三类数据:`PlayerProgress`(600 关星级/完成态)、`Settings`、`Stats`。iCloud 同步(P1)用 SwiftData **内建**的 `ModelConfiguration(cloudKitDatabase: .automatic)` —— 修正 PRD §7 原文的 `NSPersistentCloudKitContainer`(那是 Core Data API,与 SwiftData 不配套)。

**理由**:本作数据量极小(几 KB 量级、无复杂查询、无关系图),SwiftData 在"简单模型"场景 2026 年已属生产可用;模型代码量最小,iCloud 一行接入。

**风险与预案**:SwiftData 的 CloudKit 同步是其最弱项(2026 年仍有零星回归报告)。预案见 §4:模型保持可映射到 Core Data 的形状,P1 启动时先做双设备同步验证,不达标即整体切 `NSPersistentCloudKitContainer`(接口被 `Persistence/` 层隔离,替换不影响上层)。

**备选与放弃原因**:Core Data 直接上 —— 同步更稳但样板重,对本量级数据过度设计;自研 JSON + iCloud 键值 —— 最轻,但 P1 的多设备冲突/合并要全手写,长期更贵。

### 2.6 特效:纯 SwiftUI,不引入游戏引擎

**选择**:彩带等粒子效果用 `TimelineView + Canvas` 自绘(七色纸片 + 重力/旋转),星级弹入、提示点亮用 `scaleEffect` + spring 动画(参数见 VDD §7)。

**理由**:本作粒子峰值 ~50–200 片,Canvas 实测量级轻松 60fps;SpriteKit 有 iOS 26 起的帧率回归社区报告(触发于触摸/重前台),且长期缺乏大更新——为一个彩带引入它不值。

**备选与放弃原因**:SpriteKit —— 仅在将来需要物理/大量粒子时局部再议(PRD §7.1 原话亦如此);Unity 等 —— 与离线小包体目标完全不符。

### 2.7 触觉:两层 API 分工

**选择**:
- 常规事件(选中、填色、提交、成功/失败通知)用 SwiftUI `.sensoryFeedback(_:trigger:)`(iOS 17+,声明式,随设置开关);
- 「打字机机械手感」的自定义波形(提交"锵"、提示逐点)用 CoreHaptics `CHHapticEngine` + AHAP 模式。

**理由**:`.sensoryFeedback` 覆盖 90% 场景且零样板;CoreHaptics 只为手感定制服务,封装在 `Services/HapticsService`,全局可关(PRD FR-P5)。

### 2.8 音频:.ambient 会话 + 预加载播放器池 + 程序化合成

**选择**:
- `AVAudioSession` 用 **`.ambient`**(默认即混音 + 尊重静音键/锁屏,PRD 无"背景音乐压过一切"的需求);
- `SoundService` 启动时预加载全部音效为 `[Sound: [AVAudioPlayer]]` 池(单个 player 不能重叠播放,同音效 2–3 个实例池);
- 音效**由脚本程序化合成**(选色咔哒、提交铿锵、上行旋律等,PRD §6.3):生成脚本放在 `Core/`(或 Tools),输出 .caf 随包内置,带 3–5 变体。

**理由**:合成音效零版权风险(契合 §1.3 美术素材原创性审查口径)、包体几 KB、参数(音高/时长/变体)可代码化调优;采样方案留作合成听感不达标的 fallback(需 CC0 来源 + 审查记录)。

### 2.9 测试:Swift Testing 为主

**选择**:`Core/Tests` 全部用 **Swift Testing**;XCUITest 仅用于少量 UI 冒烟(教程走通、VoiceOver 标签存在性)。引擎测试矩阵对应 PRD §11:

- `evaluate` 全枚举:840 密码 × 全部合法猜测抽样(或全量 840×2401 视性能),断言直接/间接**严格等价**(验收 A4);
- 边界用例:PRD A1–A3、A6 逐一固化为参数化测试;
- PRNG 确定性:同 seed 同关卡表,跨运行字节级一致;
- 求解器验证:`validate` executable 验证 600 关每关 ≤6 次玩家猜测可解(A11),作为 CI 门槛而非仅单测。

**理由**:Swift Testing 自 Xcode 16 起稳定,参数化(`@Test(arguments:)`)与全枚举是天作之合;XCTest 仅在 UI 测试层保留。

### 2.10 CI:GitHub Actions 双轨

**选择**(草案,`swift test` 成本约为 macOS runner 的 1/8):

```yaml
# .github/workflows/ci.yml(骨架示意)
jobs:
  core:                        # 引擎 + 关卡工具:Linux,快且便宜
    runs-on: ubuntu-24.04      # 预装 Swift 6.4
    steps:
      - uses: actions/checkout@v4
      - run: swift test --package-path Core
      - run: swift run --package-path Core validate   # 关卡表门槛(A4/A11)
  ios:                         # 构建 + UI 冒烟:仅 PR 与发布分支
    runs-on: macos-26          # Xcode 27
    steps:
      - uses: actions/checkout@v4
      - run: xcodebuild -scheme Neonigma -destination 'platform=iOS Simulator,name=iPhone 17' build test
```

**理由**:关卡表由 CI 重新生成并 diff,保证"任何设备同一关卡密码一致"可复核;引擎测试放 Linux 把 macOS 分钟数留给构建。

### 2.11 本地化与无障碍

**选择**:单一 `Localizable.xcstrings`,`en` + `zh-Hans`,源语言 zh-Hans;文案 100% 走 catalog(含教程/结算儿童向文案)。无障碍按 PRD §5:色盲符号(`sym` 叠加,VDD §8)、VoiceOver 逐格朗读、Reduce Motion 全局降级、≥44pt 热区。

**理由**:String Catalogs 是 2026 标准(单文件、Xcode 自动提取、复数规则内建);Xcode 26 起对 SPM 包内字符串目录的支持也已修复——但本作文案全部留在 App target,规避该历史坑。

### 2.13 第三方依赖策略

**选择**:**运行时零第三方依赖**。开发期工具(如 swift-format)经评审后可用。

**理由**:PRD §5 隐私要求"无第三方 SDK、隐私清单齐备、COPPA/GDPR-K";零依赖同时把供应链审查成本降为零。这条是硬约束,新增依赖必须走评审并更新本文档。

**商业化配套**(PRD §9 已定稿,2026-10-01):方案 A **买断制**,App Store 付费应用形态 —— 无 StoreKit/IAP 集成、无内容解锁状态层;付费应用协议(Paid Apps Agreement)在上架前于 App Store Connect 签署即可。

## 3. 修订对照:与 PRD §7 的差异

| PRD §7 原文 | 本文档 | 原因 |
|---|---|---|
| iCloud 同步用 `NSPersistentCloudKitContainer` | SwiftData 内建 `cloudKitDatabase` 集成 | 原 API 属 Core Data,与 SwiftData 不配套 |
| 如需复杂粒子再局部引入 SpriteKit | 明确**不引入** SpriteKit | iOS 26 帧率回归报告;Canvas 足够 |
| 「工程验证脚本(随仓库)」 | 具体化为本地 SPM 包 `Core/` + 两个 executable | 可独立运行、可上 Linux CI |
| —(未提) | 新增:Swift 6 语言模式、Swift Testing、GitHub Actions、String Catalogs、零依赖策略 | 2026 年新基线 |

## 4. SwiftData → Core Data 降级预案(触发条件与步骤)

**触发条件**(P1 启动 iCloud 同步时验证):双设备同步出现数据丢失/不同步且无法在 2 周内定位;或 Apple Developer Forums 出现与本品模型同型的大面积回归。

**步骤**:①`Persistence/` 内模型改动为 Core Data 版本化 schema(字段一一对应,本作模型 3 个实体,工作量 1–2 天);②容器换 `NSPersistentCloudKitContainer`;③上层(Features/Services)零改动——接口已在 `Persistence/` 隔离;④本地数据一次性迁移(启动时读旧 store 导入)。

## 5. M1 启动清单(工程骨架一次成型)

1. `git init` + 上述目录结构 + `swift test` 绿灯(引擎空壳 + 1 个 Swift Testing 样例);
2. `Core`:evaluate / SplitMix64 / LevelTable + 全枚举测试(PRD M1 退出标准);
3. App:Xcode 27 文件夹式工程,引用本地包;首屏(主菜单)+ 对局页棋盘(直接按 VDD §10 映射);
4. `.github/workflows/ci.yml` 双轨就位;
5. 音效合成脚本产出第一版 5 音效(咔哒×2、锵、成功旋律、失败双音)。
